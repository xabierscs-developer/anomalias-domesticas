01 / Del aviso a la solución

Un caso completo: la nevera de Vera

Cada vez que Vera abre la nevera, aparece un imán con una conversación de mañana. ¿Cómo atiende la oficina este problema?

1

Registrar el fenómeno

La oficina indica vivienda, descripción, disciplina TEMPORAL y peligrosidad 3. El servidor comprueba los datos y asigna fecha actual y estado REPORTADA.

Ver petición · POST /api/anomalias 
{
  "viviendaId": 1,
  "titulo": "La nevera recuerda el futuro",
  "descripcion": "Cada apertura deja un mensaje sobre algo que ocurrirá mañana.",
  "disciplina": "TEMPORAL",
  "peligrosidad": 3
}

El servidor devuelve 201 Created con el ID generado. Para continuar este ejemplo con datos ya existentes, usa la anomalía inicial 1, también temporal y de nivel 3.

2

Buscar a alguien que pueda atenderlo

No basta con encontrar un especialista. Tiene que estar activo, compartir disciplina, tener autorización suficiente y no estar ocupado.

Hora VueltaTemporal · Nivel 4Compatible si está libre
Tomás TodavíaTemporal · Nivel 1Nivel insuficiente
Olivia SusurroSonora · Nivel 2Disciplina incorrecta

GET /api/especialistas/disponibles?anomaliaId=1

3

Iniciar la intervención

Al asignar la anomalía 1 a la especialista 1, el fenómeno pasa a EN_ESTUDIO. Se crea una intervención abierta y Hora queda ocupada.

Ver petición · POST /api/intervenciones 
{
  "anomaliaId": 1,
  "especialistaId": 1
}

No puede haber dos intervenciones abiertas para el mismo especialista ni para la misma anomalía. Si intentas hacerlo, recibirás 409 Conflict.

4

Cerrar y guardar lo que ocurrió

Hora redacta un informe. El resultado cambia el estado de la anomalía, puede aumentar su peligrosidad y deja libre a la especialista. El intento permanece en el historial.

02 / Qué guardamos

Cuatro entidades. Un mundo bastante raro.

VIVIENDA

El lugar

Dirección, residente, contacto e instrucciones de acceso.

«No usar el timbre: avisa al vecino de ayer».

ANOMALÍA

El problema

Fenómeno, disciplina, peligrosidad, estado y fecha de reporte.

Un dormitorio de nueve metros contiene una estación de tren.

ESPECIALISTA

La persona adecuada

Nombre, disciplina, nivel de autorización y actividad.

Una experta en reflejos no arregla problemas temporales.

INTERVENCIÓN

El intento

Relaciona anomalía y especialista. Guarda inicio, fin, resultado e informe.

Sin fecha de fin está abierta; al cerrar conserva su historia.

Una vivienda puede tener varias anomalías. Cada anomalía puede acumular varias intervenciones. Cada intervención la realiza un especialista.

03 / No todo acaba bien

¿Qué pasó al desenchufar la nevera?

Ejemplo independiente: empezamos siempre con una anomalía en estudio, de peligrosidad 3, y una intervención abierta. Elige un resultado para ver sus consecuencias.

RESULTADO DEL EJEMPLO

La nevera vuelve a obedecer al presente.

La anomalía queda contenida. El intento se cierra y la especialista puede atender otro caso.

Estado: CONTENIDAPeligrosidad: 3 → 3Especialista: libre
Ver petición · PATCH /api/intervenciones/{id}/cierre 
{
  "resultado": "CONTENIDA",
  "informe": "Se aisló la nevera del próximo jueves. Ya solo conserva comida."
}

Sustituye {id} por el ID que devolvió el inicio de la intervención.

  • CONTENIDA: pasa a contenida y mantiene peligrosidad.
  • SIN_CAMBIOS: vuelve a reportada, mantiene peligrosidad y puede atenderse otra vez.
  • EMPEORADA: pasa a desbordada y sube un nivel, sin superar 5.
  • Nunca dos cierres: cerrar otra vez la misma intervención devuelve 409 y no repite los efectos.

04 / Primero lo urgente

No atendemos por orden de llegada.

La prioridad combina peligro, antigüedad y desbordamiento. No se guarda en una tabla: se calcula al consultar.

peligrosidad × 10 + días completos (0–7) × 2 + 20 si está desbordada
Prioridad34

3 × 10 + 2 × 2 = 34 puntos.

Calculadora local, sin llamadas al servidor. Con más de siete días, la antigüedad solo aporta 14 puntos. En estudio o contenida: prioridad 0, porque no está pendiente de asignación. El backend calculará los días completos a partir de fechas UTC, nunca con puntos negativos.

05 / El reto más allá del CRUD

Repartir trabajo sin duplicar personas.

GET /api/guardia/propuesta calcula una sugerencia de guardia. No abre intervenciones ni cambia estados.

El algoritmo que construirás

  1. Recoger los casos pendientes sin intervención abierta.
  2. Ordenar por prioridad, después por fecha más antigua y finalmente por ID menor.
  3. Buscar especialistas activos, compatibles y libres.
  4. Elegir el nivel suficiente más bajo; en empate, el menor ID.
  5. Reservar cada persona solo una vez dentro de la propuesta.
  6. Explicar los casos sin candidato y continuar con los demás.

06 / Qué aprenderás construyéndolo

Guardar datos es solo el principio.

Una API clara

DTO de entrada y salida, validaciones, respuestas HTTP y manejo global de errores.

Consultas útiles

Filtros combinados, paginación, historial de intentos y resumen de la ciudad.

Lógica con consecuencias

Condiciones, estados, transacciones, cálculos, listas ordenadas y recursos limitados.

Ejemplo de búsqueda con filtros y paginación
GET /api/anomalias?estado=DESBORDADA&peligrosidadMinima=3&page=0&size=5

Primera página de hasta cinco anomalías desbordadas con peligrosidad de tres o más. Los filtros se combinan con AND; se ordena por fecha de reporte descendente, no por prioridad.
